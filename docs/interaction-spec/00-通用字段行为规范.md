# 00 · 通用字段行为规范

> **适用范围**：本文件描述参考实现 `variant-form` 中**所有字段组件共享**的行为契约。
> 参考源码：`variant-form/src`（默认位于仓库同级目录，可用 `VARIANT_FORM_SRC` 覆盖）
>
> **为什么先读这一章**：25 个字段组件的单个模板平均只有 4KB，而共性层（`fieldMixin.js` 613 行 +
> `form-item-wrapper.vue` 331 行 + `form-render/index.vue` 721 行）接近 50KB。
> **每个字段组件 60–70% 的可观察行为来自共性层，不在它自己的模板里。**
> 只抄模板、不抄共性层，就是"看着一样、一操作就露馅"的根因。

## 一、组件契约

### 1.1 每个字段组件的固定结构

参考实现的每个字段组件（`*-widget.vue`）都由三块拼成：

```js
mixins: [emitter, fieldMixin, i18n],
props: { field, parentWidget, parentList, indexOfParentList, designer,
         designState, subFormRowIndex, subFormColIndex, subFormRowId },
components: { FormItemWrapper },
inject: ['refList', 'formConfig', 'globalOptionData', 'globalModel'],  // 选项类组件额外 inject getOptionData
data() { return { oldFieldValue: null, fieldModel: null, rules: [] } }
```

模板永远是：

```html
<form-item-wrapper :designer :field :rules="rules" :design-state ...>
  <el-xxx ref="fieldEditor" v-model="fieldModel" ... />
</form-item-wrapper>
```

### 1.2 三个必须照搬的约定

| 约定 | 值 | 原因 |
|---|---|---|
| `componentName` | **固定 `'FieldWidget'`** | `VFormRender.setFormData` / `reloadOptionData` 依赖 `broadcast('FieldWidget', ...)` 逐级向下派发；取名不同就收不到 |
| 编辑控件的 ref | **固定 `'fieldEditor'`** | `getFieldEditor()` / `focus()` / `resetField()` 都按这个名字取引用 |
| `created` 调用顺序 | 见 1.3 | 顺序错会导致校验规则或 refList 注册失效 |

### 1.3 生命周期契约

```
created()                       // ⚠️ 顺序不可调换
  initOptionItems()             // 【仅选项类 radio/checkbox/select/cascader】其他组件没有这一行
  initFieldModel()              // 初始化本地值 + oldFieldValue + 上传文件列表
  registerToRefList()           // 注册到全局 refList
  initEventHandler()            // 监听 setFormData / field-value-changed / reloadOptionItems
  buildFieldRules()             // 构建校验规则
  handleOnCreated()             // 执行用户配置的 onCreated 字符串代码

mounted()
  handleOnMounted()             // 执行 onMounted

beforeDestroy()
  unregisterFromRefList()       // 从 refList 注销
```

⚠️ **`handleOnCreated` / `handleOnMounted` 没有 `designState` 判断**——设计态下也会执行用户在属性面板里写的代码。
（`emitAppendButtonClick` / `handleButtonWidgetClick` 则有判断，设计态不触发。）

## 二、数据模型（最关键的一节）

### 2.1 两个对象，一个真值源

```
VFormRender.formDataModel          ← 真值源，即表单数据对象
      │ provide: { globalModel: { formModel: this.formDataModel } }
      ▼
字段组件 fieldMixin.computed.formModel   ← 引用同一个对象
      │
      │ 组件内部持有一份本地副本
      ▼
字段组件 data.fieldModel                 ← v-model 绑定的就是它
```

**`fieldModel` 是本地副本，`formModel[name]` 才是真值源。** 二者在 `created` 时建立关系，之后靠事件单向同步：

```
用户操作 → v-model 改 fieldModel → @change → handleChangeEvent(value) → syncUpdateFormModel(value) → 写回 formModel
外部调用 → setFormData → broadcast → setValue(newValue) → 改 fieldModel + 写回 formModel
```

### 2.2 初始化语义 `initFieldModel()` — 最容易抄错的地方

`fieldMixin.js:36-76`

```js
if (!this.field.formItemFlag) return                      // ① 非表单字段直接跳过

// ② 子表单内（且运行态）走特殊分支，见第七章
if (this.subFormItemFlag && !this.designState) { ... }

// ③ 普通字段
if (formModel[name] === undefined && defaultValue !== undefined) {
    fieldModel = defaultValue                              // 只改本地副本！不写回 formModel
} else if (formModel[name] === undefined) {
    formModel[name] = null                                 // 无默认值 → 真值源置 null（用 = 直接赋值）
} else {
    fieldModel = formModel[name]
}
oldFieldValue = deepClone(fieldModel)
initFileList()
```

⚠️ **重要细节**：`VFormRender.created()` 会先调 `buildFormModel()`（`form-render/index.vue:202`），
它已经用 `defaultValue` 填过 `formDataModel` 了（`form-render/index.vue:271-277`）。
父组件 `created` 早于子组件 `created`，所以**正常情况下走不到第 ③ 分支的第一条**——`formModel[name]` 已经有值了。

这条分支只在外部直接调用 `setFormJson` 等边界场景生效。抄实现时**必须保留**它，但别指望它承担默认值职责。

### 2.3 默认值的真正来源有两个，且优先级不同

| 场景 | 谁负责填默认值 | 位置 |
|---|---|---|
| 常规渲染 | `VFormRender.buildDataFromWidget` | `form-render/index.vue:202-279` |
| 外部传 `formData` prop | **外部值优先**，`deepClone` 后覆盖默认值 | `form-render/index.vue:274-277` |
| 边界（子组件先于父初始化）| `initFieldModel` 第 ③ 分支 | `fieldMixin.js:66-70` |

判定条件是 `this.formData.hasOwnProperty(name)`（**不是** `formDataModel`）。

### 2.4 设计态不写数据源

`syncUpdateFormModel()` 第一行就是 `if (!!this.designState) return`。

**设计态下 `fieldModel` 只是画布上的展示值，永远不写进 formModel。** 设计器改默认值时靠 `refreshDefaultValue()` 刷新画面：

```js
refreshDefaultValue() {                       // fieldMixin.js:177
  if (designState === true && defaultValue !== undefined) fieldModel = defaultValue
}
```

### 2.5 字段名与 prop 路径

```js
getPropName() {                               // fieldMixin.js:28
  if (subFormItemFlag && !designState) return `${subFormName}.${subFormRowIndex}.${fieldName}`
  return fieldName
}
```

这个值直接作为 `el-form-item` 的 `:prop`（`form-item-wrapper.vue:16`），
子表单内是 `子表单名.行号.字段名` 三段路径，对应 formModel 的嵌套结构。

## 三、事件语义

### 3.1 三种处理函数的差异（务必区分）

| 处理函数 | 写 formModel | 触发 `formChange` | 触发 `onChange` | 触发字段校验 | 触发 `onXxx` |
|---|---|---|---|---|---|
| `handleInputCustomEvent(value)` | ✅ | ❌ **不触发** | ❌ **不触发** | ✅ 清错误 | `onInput` |
| `handleChangeEvent(value)` | ✅ | ✅ | ✅ | ✅ 清错误 | `onChange` |
| `handleFocusCustomEvent(event)` | ❌ | ❌ | ❌ | ❌ | `onFocus` |
| `handleBlurCustomEvent(event)` | ❌ | ❌ | ❌ | ❌ | `onBlur` |

`fieldMixin.js:316-353`

⚠️ **`@input` 与 `@change` 的语义差别是本规范里最容易抄丢的一条**：
参考实现里 `input` **只同步数据 + 清除已有校验错误，不广播 change 事件**；
`change` 才完整广播（`formChange` + `onChange`）。

⚠️ 参考注释（`fieldMixin.js:316`）：**输入框的"清除"小按钮会同时触发 `change` 和 `input`**，两者都会跑一遍。

### 3.2 `oldFieldValue` 的维护规则

`onChange(value, oldValue)` 的第二个参数来自 `oldFieldValue`，它的更新时机很讲究：

```
focus  → oldFieldValue = deepClone(fieldModel)     // 进入编辑前先存档
change → emitFieldDataChange(value, oldFieldValue) // 用存档当"旧值"
         oldFieldValue = deepClone(value)          // 然后刷新存档
```

⚠️ 注释明确写了（`fieldMixin.js:320`）：**number 之类的组件一般不触发 `focus` 事件**，
所以 `handleChangeEvent` 里必须手工刷新 `oldFieldValue`，否则第二次 change 拿到的 oldValue 是错的。

### 3.3 事件向外传播的链路

```
handleChangeEvent(value)
  ├─ syncUpdateFormModel(value)                       // 写 formModel
  ├─ emitFieldDataChange(value, oldFieldValue)
  │    ├─ $emit('field-value-changed', [new, old])    // 给子表单容器听
  │    └─ dispatch('VFormRender', 'fieldChange',      // 逐级向上找到 VFormRender
  │                [name, new, old, subFormName, subFormRowIndex])
  │         └─ VFormRender.handleFieldDataChange()
  │              ├─ formConfig.onFormDataChange(fieldName, new, old, formModel, subFormName, subFormRowIndex)
  │              └─ $emit('formChange', fieldName, new, old, formDataModel, subFormName, subFormRowIndex)
  ├─ oldFieldValue = deepClone(value)
  └─ dispatch('VFormRender', 'fieldValidation', [getPropName()])
       └─ $refs.renderForm.validateField(fieldName)   // 清除该字段已有错误提示
```

⚠️ `dispatch` 是**逐级向上按 `componentName` 查找**（`utils/emitter.js:11-25`），不是 `$emit` 直接冒泡。
链条上任何一层节点的 `componentName` 写错，事件就断。

## 四、校验语义

> ✅ **本仓库已实现**（第 3 步）。落点：
> `core/src/form/validators.ts`（内置校验器）、`runtime/src/context.ts`
> （`buildFieldRules` / `validateField` / `validateAll` / `getFieldError`）、
> `runtime/src/renderer.ts`（blur/change 接线）、`materials/FormItem.vue`（错误展示）。
>
> **两处有意偏离**（详见 [README 7.7](./README.md)）：
> 1. **`trigger` 的区分保留但不生效**——因为参考实现用"空 trigger 调 `validateField`"跑全部规则，
>    净效果就是 blur/change 都跑全部；本实现调用方默认传空。
> 2. **隐藏字段不产生任何规则**——消掉参考实现 `if (!formItemFlag && hidden)` 那个恒假守卫带来的不一致。
>
> **未实现**：`onValidate`（`new Function` 执行用户代码，本仓库物料清单未声明该配置项）。

### 4.1 规则构建 `buildFieldRules()` — `fieldMixin.js:191-237`

```
前置守卫：if (!formItemFlag && hidden) return      ← ⚠️ 是 && 不是 ||，注意语义
清空已有 rules（splice，保持数组引用不变，因为 rules 是传给子组件的 prop）
```

**规则一：必填**

```js
{ required: true,
  trigger: ['blur'],                              // ⚠️ 只有 blur，故意去掉 change
  message: requiredHint || i18n('render.hint.fieldRequired') }
```

> ⚠️ **源码注释原文**：`去掉change事件触发校验，change事件触发时formModel数据尚未更新，导致radio/checkbox必填校验出错！！`
>
> 这条"考古知识"必须照搬。抄成 `['blur','change']` 会在单选/多选上稳定复现"改完值还报必填"。

**规则二：内容校验**

```js
{ validator: FormValidators[vldName] 或 FormValidators.regExp,
  trigger: ['blur', 'change'],                    // ⚠️ 这条有 change，和必填不同
  label: field.options.label,
  errorMsg: field.options.validationHint }
```

- `validation` 的值命中内置校验器名 → 用对应校验器
- 未命中 → **当作正则字符串**，走 `FormValidators.regExp`

**规则三：自定义校验**

```js
{ validator: (rule, value, callback) => new Function('rule','value','callback', onValidate).call(this, ...),
  trigger: ['blur', 'change'],
  label }
```

### 4.2 内置校验器清单 — `utils/validators.js`

| 名称 | 正则 | 默认错误文案 |
|---|---|---|
| `number` | `/^[-]?\d+(\.\d+)?$/` | `[label]包含非数字字符` |
| `letter` | `/^[A-Za-z]+$/` | `[label]包含非字母字符` |
| `letterAndNumber` | `/^[A-Za-z0-9]+$/` | `[label]只能输入字母或数字` |
| `mobilePhone` | `/^[1][3-9][0-9]{9}$/` | `[label]手机号码格式有误` |
| `letterStartNumberIncluded` | `/^[A-Za-z]+[A-Za-z\d]*$/` | `[label]必须以字母开头，可包含数字` |
| `noChinese` | `/^[^\u4e00-\u9fa5]+$/` | `[label]不可输入中文字符` |
| `chinese` | `/^[\u4e00-\u9fa5]+$/` | `[label]只能输入中文字符` |
| `email` | `/^([-_A-Za-z0-9.]+)@([_A-Za-z0-9]+\.)+[A-Za-z0-9]{2,3}$/` | `[label]邮箱格式有误` |
| `url` | 见源码 | `[label]URL格式有误` |
| `regExp` | `eval(rule.regExp)` | `rule.errorMsg \|\| '[label]invalid value'` |

⚠️ **所有内置校验器"空值不校验"**：

```js
if (isNull(value) || (value.length <= 0)) { callback(); return }
```

即空字符串 / null 时**直接通过**——必填由 `required` 规则单独负责，两者不重叠。

⚠️ `noBlankStart` / `noBlankEnd` **声明了但是空函数，永远通过**（`validators.js` 注释"暂未实现"）。
属性面板的校验器下拉里也没列这两项。

⚠️ `validateFn` 里对 `value.length` 取长度。当 `value` 是数字（number 组件）时 `length` 为 `undefined`，
`undefined <= 0` 为 `false`，所以**不会**被当成空值跳过，会继续走正则——这是可观察的行为差异，抄实现时保持原样。

⚠️ `new Function` + `eval`：参考实现大量使用。移植到 Vue3/TS 时若加 CSP 或严格模式会失效，
需要显式决策（建议保留等价能力，但要记录为有意偏离）。

### 4.3 规则的动态开关

| 方法 | 行为 | ⚠️ 坑 |
|---|---|---|
| `clearFieldRules()` | `rules.splice(0, length)` 清空 | 非 `formItemFlag` 直接 return |
| `disableChangeValidate()` | **清空每条 rule 的 `trigger` 数组** | 不只是去掉 change，是把所有 trigger 清光 → **完全禁用触发** |
| `enableChangeValidate()` | 向每条 `trigger` push `'blur'` 和 `'change'` | **重复调用会累积重复项** |
| `setHidden(true)` | `clearFieldRules()` | |
| `setHidden(false)` | `buildFieldRules()` | |
| `setRequired(flag)` | 改 option + `buildFieldRules()` | |

⚠️ `el-form` 上有 `:validate-on-rule-change="false"`（`form-render/index.vue:13`）——
规则变化**不会自动触发校验**。没有这一条，改必填会立刻全线报错。

### 4.4 校验错误提示的显示方式（容易漏）

`form-item-wrapper.vue` 里**没有给 `el-form-item` 传 `required` prop**，必填星号是纯 CSS 画的：

```css
.required ::v-deep .el-form-item__label::before { content: '*'; color: #F56C6C; margin-right: 4px; }
```

class 的拼装（`form-item-wrapper.vue:17`）：

```
[ selected ? 'selected' : '', labelAlign, customClass, options.required ? 'required' : '' ]
```

## 五、全局引用表 `refList`

### 5.1 注册语义 — `fieldMixin.js:131-156`

```js
registerToRefList(oldRefName):
  if (refList === null || !options.name) return          // ⚠️ 名字为空则不注册
  if (子表单内 && 运行态) {
      if (oldRefName) delete refList[oldRefName + '@row' + subFormRowId]
      refList[options.name + '@row' + subFormRowId] = this
  } else {
      if (oldRefName) delete refList[oldRefName]
      refList[options.name] = this
  }

unregisterFromRefList():  // beforeDestroy 时删除同名 key
```

`VFormRender` 自己注册为 `refList['v_form_ref']`（`form-render/index.vue:296-298`）。

### 5.2 ⚠️ 三个可观察的边界行为

1. **`name` 为空字符串的组件不注册**——设计器里刚拖进来还没命名的组件，`getWidgetRef` 找不到。
2. **`name` 重复会静默覆盖**——后创建的组件覆盖先创建的，没有任何警告。
3. **`refList` 是 `provide` 出去的普通对象**（`widgetRefList`），不是 Vue 的响应式数据；
   它只在运行期当"服务定位器"用。

> ✅ **本仓库的实现**（已完成）：`RuntimeContext` 用 `node.name → nodeId` 索引实现同名寻址
> （`resolveNodeId` / `getWidgetRef`），重名同样后者覆盖前者；无 `name` 时回退到节点 id。
> 返回的是 `FieldHandle` 句柄而非组件实例——本架构里字段读写都是节点级操作，不需要实例。
> 见 `packages/runtime/src/field.ts` 与 [README 7.5](./README.md)。

## 六、选项类组件专属通道

适用：**radio / checkbox / select / cascader**（其他组件没有这一套）

### 6.1 三入口

```
VFormRender.optionData (prop)
  │ provide: globalOptionData = this.optionData
  │          getOptionData   = () => this.optionData      // ⚠️ 用闭包，不用注入的对象
  ▼
initOptionItems(keepSelected)                               // fieldMixin.js:158，created 时调用
  if (designState) return                                   // ⚠️ 设计态直接跳过
  取 getOptionData()[字段名]
  有值 → keepSelected ? reloadOptions(v) : loadOptions(v)
```

⚠️ 源码注释解释了为什么用 `getOptionData()` 而不是注入的 `globalOptionData`：
**异步更新 option-data 之后，注入的对象拿不到最新值**。这个坑必须照搬。

### 6.2 `loadOptions` 与 `reloadOptions` 当前**行为完全相同**

```js
loadOptions(options)   { this.field.options.optionItems = deepClone(options) }   // 清空字段值那行被注释掉了
reloadOptions(options) { this.field.options.optionItems = deepClone(options) }
```

`fieldMixin.js:529-540`。JSDoc 写着"loadOptions 加载选项并清空字段值"，
但 `this.clearSelectedOptions()` **已被注释**。**文档与实现矛盾，以实现为准。**

### 6.3 动态刷新

```
VFormRender.reloadOptionData(widgetNames)        // 传字符串或数组，不传=全部
  └─ broadcast('FieldWidget', 'reloadOptionItems', [names])
       └─ 组件 initOptionItems(true)             // ⚠️ 固定传 true → 走 reloadOptions，不清值
```

### 6.4 选项级操作

```js
disableOption(optionValue) / enableOption(optionValue)   // 按 value 匹配，改 opt.disabled
getOptions()                                             // 返回 field.options.optionItems
clearSelectedOptions()                                   // checkbox/多选select → []；其他 → ''
                                                          // ⚠️ 只对 checkbox/radio/select 生效，其他直接 return
```

## 七、子表单（sub-form）语义

子表单是唯一会让上述规则分叉的容器。**移植时如果第一期不做子表单，本节可以先跳过，但必须留出扩展点。**

| 维度 | 普通字段 | 子表单内字段（运行态） |
|---|---|---|
| prop 路径 | `name` | `子表单名.行号.字段名` |
| refList key | `name` | `name@row行ID` |
| 数据写入 | `formModel[name] = v` | `formModel[子表单名][行号][name] = v` |
| 初始化 | `initFieldModel` 第 ③ 分支 | 第 ② 分支（直接写 `subFormData[rowIndex][name]`） |
| onChange 签名 | `onChange(value, oldValue)` | `onChange(value, oldValue, subFormData, rowId)` |
| `resetField()` | 执行 | **直接 return，跳过** |
| `setFormData` 广播 | 生效 | ⚠️ **不生效**（见下） |

⚠️ **源码注释原文**（`fieldMixin.js:424-427`）：
> `VFormRender的setFormData方法不会触发子表单内field-widget的setValue方法，
> 因为setFormData方法调用后，子表单内所有field-widget组件已被清空，接收不到setFormData事件！！`

⚠️ **魔法数字**：子表单初始化后 **`setTimeout(..., 800)`** 才主动触发一次 `onChangeForSubForm`
（`fieldMixin.js:56-58`），注释写"延时触发onChange事件，便于更新计算字段"。移植时可改成显式时机，但要记录下来。

## 八、公开 API 全集（`fieldMixin` 提供给每个字段组件）

### 8.1 取值 / 赋值 / 重置

| 方法 | 行为 | ⚠️ |
|---|---|---|
| `getValue()` | 返回 `fieldModel` | 上传组件曾返回 `fileList`，**已注释**，现在统一返回 `fieldModel` |
| `setValue(v)` | 改 `fieldModel` + `initFileList()` + 写 formModel + 广播 change | **仅当 `formItemFlag` 为真**才执行，否则静默无操作 |
| `resetField()` | `setValue(field.options.defaultValue)`；上传组件额外 `clearFiles()` + 清空 `fileList` | 子表单内直接 return |
| `focus()` | `getFieldEditor().focus()` | 编辑器无 `focus` 方法则静默跳过 |
| `getFieldEditor()` | 返回 `$refs['fieldEditor']` | 依赖固定 ref 名 |
| `getFormRef()` | `refList['v_form_ref']` | |
| `getWidgetRef(name, showError)` | 按名取组件实例；找不到且 `showError` 为真时弹 `$message.error` | |

### 9.1 数据

| 方法 | 行为 | ⚠️ |
|---|---|---|
| `getFormData(needValidation = true)` | 返回 **Promise**；`false` 时同步返回 `formDataModel` | 校验失败 → **reject**(i18n 的 validationFailed 文案) |

⚠️ **`setFormJson` 里的关键注释**（`form-render/index.vue:432-433`）：
> `this.formDataModel = {}   //清空表单数据对象（有bug，会导致表单校验失败！！）`

### 9.2 状态与校验

| 方法 | 行为 |
|---|---|
| `validateForm(callback)` | `renderForm.validate(valid => callback(valid))` |
| `clearValidate(props)` | 透传 `renderForm.clearValidate` |
| `resetForm()` | 先重置所有子表单 → 再逐字段 `resetField()`（**跳过子表单字段**）→ `$nextTick` 后 `clearValidate()` |
| `disableForm()` / `enableForm()` | 遍历 `refList` 全部组件；子表单走 `disableSubForm/enableSubForm`，其他走 `setDisabled` |
| `disableWidgets(names)` / `enableWidgets(names)` | 字符串或数组；找不到则**在子表单里按 name 找各行实例** |
| `hideWidgets(names)` / `showWidgets(names)` | 同上，走 `setHidden` |

⚠️ `resetForm` 的顺序不能变：先重置值，**`$nextTick` 之后**才 `clearValidate`，
否则 `resetField` 触发的校验错误提示会留在界面上。

## 十、设计态通用行为（`form-item-wrapper.vue`）

### 10.1 标签与宽度

```js
label()        { labelHidden ? '' : options.label }

labelWidth()   {
    labelHidden        → designState ? 5 : 0      // ⚠️ 设计态给 5px，为了留出点击热区选中组件
    options.labelWidth → 用它
    designer           → designer.formConfig.labelWidth
    否则                → formConfig.labelWidth
}

labelAlign()   { options.labelAlign || (designer ? designer.formConfig : formConfig).labelAlign || 'label-left-align' }
customClass()  { options.customClass ? options.customClass.join(' ') : '' }   // ⚠️ 是数组
```

⚠️ `customClass` 在 schema 里是**数组**（`addCssClass` 也是 push 进去的），不是字符串。

### 10.2 渲染条件

```html
<el-form-item v-if="field.formItemFlag && (!field.options.hidden || designState === true)">
```

**`hidden` 的组件在运行态不渲染、在设计态照常渲染**（带一个隐藏图标标识）。

### 10.3 选中态与操作条

| 元素 | 位置 | 内容 | 出现条件 |
|---|---|---|---|
| `outline: 2px solid 主色` | 组件外框 | | `designer.selectedId === field.id` |
| `.field-action` | 底部右对齐 | 选父级 / 上移 / 下移 / 删除 | 选中时；上移下移仅 `parentList.length > 1` |
| `.drag-handler` | 左上角 | 拖拽把手 + **组件类型中文名** + hidden 时的隐藏图标 | 选中时 |

删除后的选中迁移规则（`form-item-wrapper.vue:176-198`）：

```
parentList.length === 1              → 选中 parentWidget（没有则 null）
是最后一个子元素（length === idx+1）→ 选中前一个
否则                                 → 选中后一个
```

删除在 `$nextTick` 里执行，且必须 `designer.formWidget.deleteWidgetRef(fieldRefName)`
（`fieldRefName` 取的是 **`designer.selectedWidgetName`**，不是当前 field 的名字——这是个隐晦依赖）。

### 10.4 鼠标选中

```html
<el-form-item @click.native.stop="selectField(field)">
```

⚠️ 用 `.stop` 阻止冒泡，并同时通知设计器两件事：
`designer.setSelected(field)` + `designer.emitEvent('field-selected', parentWidget)`（把**父组件**对象发出去）。

## 十一、⚠️ 已知坑清单（移植时的雷区）

| # | 坑 | 后果 |
|---|---|---|
| 1 | 必填规则的 `trigger` 只有 `['blur']` | 加 change 会让 radio/checkbox 必填校验误报 |
| 2 | `@input` 不广播 change | 抄成和 change 一样会导致 `formChange` 触发两次 |
| 3 | `oldFieldValue` 必须在 change 里刷新 | 否则 `onChange(value, oldValue)` 的 oldValue 是错的 |
| 4 | `formDataModel` 引用不可替换 | 替换后 `el-form` 校验失效 |
| 5 | `refList` 的 key 在子表单里带 `@rowN` 后缀 | 不带后缀则子表单字段互相覆盖 |
| 6 | `componentName` 必须叫 `FieldWidget` | 否则收不到 `setFormData` / `reloadOptionItems` |
| 7 | 编辑控件 ref 必须叫 `fieldEditor` | 否则 `focus()` / `resetField()` 失效 |
| 8 | `loadOptions` 其实**不清空**已选值 | 按 JSDoc 实现会和参考行为不一致 |
| 9 | `optionData` 必须走 `getOptionData()` 闭包 | 用注入的对象在异步更新后拿到旧值 |
| 10 | 内置校验器空值直接通过 | 若改成"空值也报错"，会和 required 规则重复报错 |
| 11 | `noBlankStart` / `noBlankEnd` 是空实现 | 误以为已支持 |
| 12 | `designState` 下不写 formModel | 设计器改默认值必须靠 `refreshDefaultValue()` |
| 13 | `onCreated` / `onMounted` 设计态也执行 | 用户代码可能在设计器里反复跑 |
| 14 | 必填星号是 CSS 画的，不是 `el-form-item` 的 required | 用组件库自带星号会双重显示 |
| 15 | 子表单 `setTimeout(..., 800)` | 时序魔法数字 |
| 16 | `disableChangeValidate` 是清空**所有** trigger | 名字误导，实际完全禁用触发 |
| 17 | `enableChangeValidate` 会累积重复 trigger | 反复调用后数组里全是重复项 |
| 18 | `setFormData` 只处理 formDataModel 已有的 key | 想新增字段必须先改 schema |
| 19 | 子表单内字段收不到 `setFormData` | 参考注释明确承认的限制 |
| 20 | 所有 `onXxx` 都是 `new Function` + `eval` | CSP / 严格模式下会失效 |

## 十二、移植到 Vue 3 + Element Plus 的决策点

以下是**无法 1:1 照搬**、必须显式决策的地方。每条都应记录在 `packages/materials/src/conformance/audit.ts` 的 `WAIVERS` 里。

| # | 参考机制 | 参考能力 | Vue 3 可选做法 | 建议 |
|---|---|---|---|---|
| 1 | `mixins: [fieldMixin]` | 每个字段组件自动获得 60+ API | ① `composable` 工厂 ② 运行期注册表 + 统一代理 | **②**：字段 API 的分发本质是"按名找组件"，用注册表比 25 个组件各自 mixin 更贴合 Schema 架构 |
| 2 | `emitter.dispatch/broadcast` 按 `componentName` 逐级查找 | 跨层级通信 | ① `provide/inject` 事件总线 ② 直接持有根表单引用 | **①**：`dispatch` 的语义就是"向上找最近的 VFormRender"，等价于 inject 根上下文 |
| 3 | `new Function` 执行 `onXxx` 字符串 | 用户在属性面板写代码 | ① 保留 `new Function` ② 换成表达式引擎（如已有 jexl） | 需明确：**保留等价能力**，但记录为有意偏离（安全/CSP） |
| 4 | `eval` 正则字符串 | `validation` 可直接填正则 | ① `new RegExp(str)` ② 表达式引擎 | **①**，安全且等价 |
| 5 | `formModel` 双向同步 | 本地副本 + 事件同步 | ✅ **已落地**：渲染器把 `update:modelValue` 接到 `RuntimeContext.setNodeValue()`，写入响应式 `overrides`，由 `resolveProp` 优先读取；值**永不写回 schema** | 接入 `FormEngine` 时只需替换 `setNodeValue` 的函数体，渲染器无需改动。详见 [README 7.4](./README.md) |
| 6 | `field.options` 单一可变对象 | 所有配置挂在 `options` 上，组件直接读写 | ✅ **已落地**：配置摊平成 props，但通过 `RuntimeContext.setNodeProp` 提供统一的"按名写配置"入口，由 `FieldHandle`（`runtime/src/field.ts`）暴露成与参考同名的 API | `setWidgetOption` 等 API 落到 `setNodeProp`：编辑进 schema 历史，预览落本地覆盖。详见 [README 7.5](./README.md) |

## 十三、验收标准（可直接转成测试用例）

### 数据模型

- [ ] 组件创建后，`formModel` 中该字段存在且等于 `defaultValue`
- [ ] 外部传 `formData` prop 时，**外部值优先于 `defaultValue`**
- [ ] 设计态修改默认值，画布立即更新，但 `formModel` **不变**
- [ ] 用户输入后 `formModel` 同步更新
- [ ] 子表单字段的 `el-form-item` 的 prop 为 `子表单名.行号.字段名`

### 事件

- [ ] 输入触发 `input`：`formModel` 更新，但 **`formChange` 不触发**、`onChange` 不触发
- [ ] 失焦/值确认触发 `change`：`formModel` 更新 + `formChange` 触发 + `onChange(value, oldValue)` 触发
- [ ] **连续两次 change，第二次的 oldValue 等于第一次的 newValue**
- [ ] `onFocus` 时 `oldFieldValue` 被更新为当前值
- [ ] 字段 change 后会调用 `validateField`，界面上该字段已有的错误提示被清除

### 校验

- [ ] `required` 为真时，标签前有红色 `*`
- [ ] 必填校验**只在 blur 触发**，change 不触发
- [ ] 单选/多选改值后，**不会**立刻报"必填"错误
- [ ] 内置校验器在**空值时通过**
- [ ] `validation` 填非内置名时按正则处理
- [ ] 自定义 `onValidate` 可拿到 `rule` / `value` / `callback`
- [ ] 切换 `hidden` 为真时校验规则被清空
- [ ] `formConfig` 或 schema 改规则时**不自动触发**校验

### API

- [ ] `setValue(v)` 更新值和 `formModel`，并触发一次 change 广播
- [ ] `setValue` 在非 `formItemFlag` 组件上静默无操作
- [ ] `resetField()` 恢复为 `defaultValue`
- [ ] `resetForm()` 后**界面上没有残留校验错误**
- [ ] `disableForm()` / `enableForm()` 影响所有字段含子表单
- [ ] `getFormData(false)` 同步返回，`getFormData(true)` 返回 Promise 且校验失败时 reject
- [ ] `setFormData` **不新增** `formDataModel` 里没有的 key
- [ ] `refList` 中 `name` 为空的组件不注册
- [ ] 同名组件后者覆盖前者

### 选项类

- [ ] 设计态**不加载** `optionData`
- [ ] 运行态 `optionData` 有对应字段时替换 `optionItems`
- [ ] `reloadOptionData(name)` 后已选值**保持不变**
- [ ] `disableOption(v)` / `enableOption(v)` 按 value 生效
- [ ] 异步更新 `optionData` 后能拿到**最新值**（验证闭包通道）

### 设计态

- [ ] `hidden` 组件在设计态可见（带隐藏图标），运行态不可见
- [ ] `labelHidden` 时设计态标签宽度为 5px、运行态为 0
- [ ] 选中组件显示蓝色 outline + 操作条 + 拖拽手柄
- [ ] 上移/下移按钮仅在 `parentList.length > 1` 时出现
- [ ] 删除后选中态按"最后一个→前一个，否则→后一个"迁移
- [ ] 点击组件会触发 `setSelected` 并向外发 `field-selected`（参数是**父组件**）
