## 一、一句话概括

这一轮不是"加功能"，是**把已有实现的偏差找出来并修掉**，同时**把发现偏差的能力建起来**
（4 层 A/B + 可执行规范 + 端到端检查）。修完的偏差里，**最有价值的三个都不是"差几像素"**，
而是功能缺失或全局参数错误。

## 四、方法论收获（比代码更值得留）

这一轮**我自己的探针/断言错了 12 次以上**，且**每次第一个结论都是"找到 bug 了"**：

| 假 bug | 真因 |
| --- | --- |
| `modelValue` 没接线 | 指纹只比 `outerHTML`，漏了 input 的 **property** |
| `columnWidth` 没接线 | 测试值是非法 CSS（`width: EFFECT`） |
| `image.width` 没接线 | override 不看类型，数字属性被塞了 `'300px'` |
| `fontSize` 没接线 | 同上 |
| `select.multiple` 没接线 | 空的多选与空单选**渲染完全相同** |
| `hidden` 断言失败 | 渲染层用 `v-if`，节点**从 DOM 移除**而非 `display:none` |
| 5 个选择器全落空 | 我们的外壳是 `lc-form-item`，不是 `el-form-item` |
| `columnWidth` 是产品 bug | 参考里**也只对子表单字段生效** |
| `number` 的 aria 不同步 | EP 的实现细节，`min`/`max` 属性是对的 |
| `select` 没有 `is-disabled` | 禁用体现在内层 input |
| `alert` 该不该有关闭按钮 | 参考的 `closable` **默认就是 true** |
| `select` 填不进值 | **下拉框不能靠打字填值** |

**结论：探针写错造出的假 bug，比漏报更危险——你会去修一个不存在的问题。**
所以每个新增检查都做了**反向验证**（把产品改坏，确认它变红）。

其它三条：

1. **"差异数少"不等于"对齐得好"** —— 卡片从"1 处差异"变成"13 处"再降到"6 处"，
   那个 1 是假象（我们当时没有任何 el- 元素可比较）。
2. **数值型结论会随前提过期** —— 提示标题行高的 15px 是字体修正前测的，字体一换就错了。
3. **注释里的假设也是 bug 源头** —— 「ElTabs 会自行选中第一个 pane」写得很像事实，
   于是没人去验，结果内容区一直是空的。
