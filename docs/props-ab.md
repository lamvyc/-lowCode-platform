# 属性面板 A/B 对比（第三层）

> 实测得出，不是读代码推测。工具：`scripts/props-ab.py`。

## 为什么需要这一层

前三层已经覆盖：**物料面板**（能拖什么）、**画布结构**（渲染在哪种容器里）、
**画布渲染**（渲染成什么样）。这一层是**能配什么**——用户真正上手改东西的地方。

三层的性质不同，命中率也不同：物料面板一次撞出 14 个标签不一致，画布层撞出 10px 宽度链，
**而这一层的结论与直觉相反**（见下）。

## 方法

两边的结构恰好对应，所以能逐项比：

| | 分组 | 行 | 标签 |
| --- | --- | --- | --- |
| 我们 | `.lc-props-panel__content .el-collapse-item` | `.lc-field` | `.lc-field__label` |
| 参考 | `.panel-container` 组件设置 pane 的 `.el-collapse-item` | `.el-form-item` | `.el-form-item__label` |

比的是：**每个分组下的属性标签序列 + 各自的控件类型**。

### ⚠️ 一个必须先修正的口径

参考的「表单设置」tab **也渲染在同一棵树里**（`基本属性 / 全局组件大小 / 数据对象名称 …`），
那是**表单级设置**，不是组件属性。第一版没 scope 到 tab pane，参考的项数虚高十几条
（单行输入 54 → 40）。**对比口径错了，结论就全错了。**

## 结果

| 物料 | 参考 | 我们 |
| --- | --- | --- |
| 单行输入 | 40 | 25 |
| 单选项 | 26 | 20 |
| 开关 | 23 | 20 |

差距比"40 vs 25"看起来的小得多，而且**性质分三类**：

### (a) 标签文案不统一 —— 真问题，和物料面板那次同类

| 参考 | 我们 |
| --- | --- |
| 显示类型 | 输入类型 |
| 占位内容 | 占位提示 |
| 必填字段 | 必填 |
| 隐藏字段标签 | 隐藏标签 |
| 组件大小 | 尺寸 |
| 组件列宽 | 控件宽度 |
| 可清除 | 可清空 |
| 显示样式 | 展示方式 |
| 显示为按钮 | 按钮样式 |
| 带有边框 | 显示边框 |
| 开关宽度（像素） | 开关宽度 |
| 开启时文字描述 | 打开文案 |

这是**可以直接对齐的**，优先级最高——它直接影响"用户找不找得到那个设置项"。

### (b) 我们**故意**藏了次级属性 —— 记豁免（我们的设计更好）

参考把几十项属性**全部平铺**；我们把次级属性放在条件下：

| 属性 | 我们的可见条件 |
| --- | --- |
| 显示字数统计 | `maxLength != null` |
| 后置按钮禁用 / 后置按钮Icon | `appendButton == true` |

**这是有意的 UX 改进，不是缺口。** 若照参考平铺，面板会长到需要大量滚动、
且充满"当前无意义"的选项。已用单测守住（见下）。

### (c) 控件类型不同 —— 我们的更好，记豁免

| 属性 | 参考 | 我们 |
| --- | --- | --- |
| 标签宽度 / 最小长度 / 最大长度 | `input`（文本框，可填任意字符串） | `number`（数字框） |

参考用纯文本框意味着能输入 `abc` 并产生非法值；我们用数字控件是更严格的选择。

## 一条配套的单测（永久守卫）

`packages/materials/src/manifest.test.ts` 的「属性面板完整性」：

> 每个 `defaultProps` 里的可配置属性，必须在 `propConfigs` 有对应项
> （`name` / `hidden` / `modelValue` 三个系统项除外）。

这条把"能力有、入口没有"变成编译期就能发现的问题。

**注意它的局限**：它查的是"有没有配置项"，**不查"配置项当前是否可见"**。
后者由 `visibleWhen` 决定，是设计意图——所以本层 A/B 报出的"缺失"里，
绝大多数是条件可见，**不能当成缺口去补**。

## 怎么复现

```bash
# 两个 dev server 都要起（参考 8090 / 本仓库 5174）
python3 scripts/props-ab.py                # 默认几个代表组件
python3 scripts/props-ab.py 单行输入 单选项
```

## 已知局限

- `按钮` / `分隔线` 这类**静态内容**物料点不中（参考侧没有 `.el-form-item`），
  抽取器需要一个回退选择器才能覆盖。
- 只比了"标签 + 控件类型"，**没比控件的可选值**（如「组件大小」的选项集合）、
  默认值、以及分组归属。
- 参考侧依赖点击选中；表格/容器类物料的选中元素与字段不同。
